For this task, I containerized the Campus Lost and Found application using Docker and Docker Compose. I created a Dockerfile for the Node.js and Express application and used a .dockerignore file to exclude unnecessary files such as node_modules. I used Docker Compose because the application requires both the Node.js application and MongoDB. Docker Compose allowed these services to run together and communicate through the Docker network. This approach also makes the application easier to run in a clean environment because the required services can be started with a single command.
I also integrated MongoDB with the application so that lost and found reports are stored in the database rather than only being kept temporarily in memory. I connected the report form to the backend API and tested the integration by submitting a report through the web interface and checking that the submitted item appeared through the /api/items endpoint. I also added the /api/student endpoint containing my name and student ID as required.
One of the main issues I encountered was getting Docker Desktop and the containers to run correctly. At one stage, port 3000 was already being used by a local Node.js process, which prevented the application container from starting. I identified the process using the port, stopped it, and then restarted the Docker Compose services. I also experienced Docker Desktop becoming unresponsive, so I restarted Docker and verified its status before rebuilding the containers.
The most challenging part of this task was understanding how the application container and MongoDB container communicate with each other. Previously, I was more familiar with running Node.js applications directly on my computer. This task helped me understand Docker networking, containerized databases, port mapping, and persistent database integration. The most rewarding part was successfully submitting a report through the browser and retrieving the stored data from MongoDB while the complete application was running through Docker.
